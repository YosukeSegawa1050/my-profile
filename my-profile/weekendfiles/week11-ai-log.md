# Week11 AIと考えたログ

## Part 1：AIと考えた1セッション

### テーマ
Week10でGitHub APIからユーザー情報を取得する方法について対話した

### 送った指示（良いプロンプトの型）

目的: GitHubユーザー情報を画面に表示する
前提: GitHub APIを使用する
見てほしい観点: fetch、async/await、エラー処理
制約: 存在しないユーザーにも対応する
出力形式: HTMLとJavaScriptのコード

### 返ってきた出力（要約）

GitHub APIへアクセスし、名前、画像、自己紹介、フォロワー数を画面に表示する方法が提案された

### "なぜ"を聞いた記録

聞いたこと: なぜresponse.okを確認する必要があるのか
返ってきた説明（要約）: fetchは存在しないユーザーでも自動的にエラーにならないため
聞く前は分からなかったが、聞いて分かったこと: response.okを確認し、問題がある場合はthrowでcatchへ移す必要があると分かった

### 出力の4分類

| 分類 | 内容 | 判断理由 |
|---|---|---|
| 採用する |fetchとasync/await |APIから順番にデータを取得できるため |
| 保留する |詳細なエラーの分類 |今回の課題では必須ではないため |
| 採用しない |取得データをすべて表示する処理 | 必要な情報だけ表示したいため|
| 要確認 | GitHub APIのURL| ユーザー名やURLが正しいか確認が必要なため|
